# 澄清 · Chengqing Cleaner

桌面深度清理工具的交互原型、实施方案和技术架构。

更新日期：2026-11-02。产品名称暂定“澄清”，当前以 macOS 桌面端为设计基准。

> 当前包含 [HTML 交互原型](index.html) 和方案文档。扫描、容量、系统状态和文件操作均为演示，尚未实现真实清理引擎，也未接入 Jev 或 LLM。新增桌面实现与技术架构为开发建议，未表示已有实现。

## 产品方案摘要

按软件识别文件用途，再按类别独立选择处理内容。缓存、日志、旧版本、用户资料、运行组件、共享依赖和模型资源均可加入方案；每项说明推荐操作、依据、影响范围、前置条件和恢复限制。

例如，同一个聊天软件可以只清理预览缓存，同时保留聊天资料、个人设置和离线文件。建议保留不等于禁止选择；前置条件未满足时，选择保存为待处理计划。

默认使用应用隔离区：先隔离、观察，再恢复或手动确认彻底清除。用户也可以显式选择直接删除。每次选择与实际操作写入同一批次账本，后续恢复、删除和空间复核追加事件。

## 桌面页面设计

当前以 `index.html` 为视觉基准：固定主窗口、环形水位容量仪表、按应用分组的连续列表、行内详情、局部滚动和固定底部操作区。

| 入口 | 主要内容 |
| --- | --- |
| 默认清理工作区 | 磁盘容量、10 项检查范围、扫描、软件分组、行内详情、方案审阅与结果 |
| 标题栏隔离区图标 | 当前隔离文件、恢复、确认彻底清除、来源记录 |
| 标题栏清理记录图标 | 本地个人资料、期间统计、批次时间线与本期总结 |
| 标题栏设置图标 | 8 套外观主题；检查范围在首页单独调整 |
| 菜单栏状态图标 | 磁盘、CPU、内存、扫描进度与缓存审阅隔离 |

软件归属融入结果内部；清理记录内嵌本地资料。当前不设侧栏、四个文字主菜单或常驻右侧检查器，早期文档中的相应布局作为历史方案。

## 桌面技术建议

采用 **Tauri 2 + React + TypeScript + Rust + SQLite**，macOS 优先。界面、只读扫描、规则、受控执行、账本和系统适配分层；主窗口与菜单栏共享任务服务。先验证少量软件的扫描与隔离恢复，再开放删除、空间复核和可选 AI。

## AI 方案摘要

当前技术建议：**本地扫描与规则引擎＋受限原生执行器，LLM 为后续可选辅助，预留 Jev 接口。**

- 本地程序提供归属、占用、引用、大小和权限等可验证证据。
- LLM 理解用户要求，调用受控的只读工具补查，分析疑难项目，解释影响和组织总结。
- Jev 指 TypeSafe 的决策模型，可评估用于固定类别判断、排序与分流；先旁路评测，再决定是否启用。
- 原生执行器校验确认范围和最新文件状态，执行隔离、恢复、删除并保存真实结果。

Jev 的结构化结果与置信度均不能直接作为允许删除的凭据。LLM 也能提供结构化判断；是否增加 Jev，取决于本产品评测中的误判率、延迟、成本和维护收益。

## 必须保留的约束

- 用户资料默认建议保留；所有类别可加入方案，处理条件独立检查。
- 同盘隔离仍占空间。文件占用、当前隔离占用和已复核磁盘净变化分别统计。
- 待处理、失败、跳过和保留项不计成功成果；隔离后再删除不重复累计。
- 统计按事件实际发生时间归入期间，空间测量记录覆盖的删除事件。
- AI 只能引用本地项目和证据标识，不能传入任意删除路径、通配符或 shell 命令。
- 大小、数量、日期和汇总由代码计算；AI 总结不能补造数字或操作结果。

## 当前状态

原型演示了容量仪表、范围配置、分类选择、行内详情、隔离恢复、清理记录、菜单栏快捷清理和主题切换。真实扫描、原生执行、持久化账本、模型接入和生产评测均待开发。

仓库没有指定开源许可证；桌面框架、官网 DMG 分发与 macOS 支持范围已有建议，待可行性验证。首批软件规则和模型供应商仍待确定。
