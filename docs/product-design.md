## 1. 产品定位

澄清是一款能够解释清理理由、允许分项决策、支持恢复与追溯的桌面深度清理工具。

用户可以在同一个软件下分别处理缓存、日志、旧版本、用户资料、运行组件和功能资源。例如：清理聊天软件的预览缓存，同时保留聊天资料和个人设置；识别旧组件后，先检查是否仍被使用，再决定如何处理。

产品要回答五个问题：

1. 这些文件属于哪个软件，承担什么作用？
2. 建议清理还是保留，依据是什么？
3. 处理后影响谁，会失去什么，需要先做什么？
4. 出现问题时能否恢复，恢复有哪些限制？
5. 每次处理了什么，文件有多大，磁盘空间实际变化多少？

核心体验：**按软件理解，按类别选择，先检查再执行，全过程留记录。**

## 2. 已确认的产品原则

| 原则 | 具体要求 |
| --- | --- |
| 桌面应用体验 | 采用桌面窗口、顶部工具栏、紧凑列表和明确的任务状态；页面围绕实际清理操作组织 |
| 主菜单置顶 | 固定为“概览、深度清理、隔离区、个人中心”，不设置主导航侧栏 |
| 所有类别都可选择 | 用户数据、运行组件、共享依赖、模型资源均可加入方案，不因“建议保留”而整类禁止选择 |
| 推荐与选择分离 | 软件提供建议，用户保留选择权；“已勾选”与“能够立即执行”分别表达 |
| 分类清理 | 同一软件可以只清缓存，保留用户资料；勾选软件不能隐含删除全部内容 |
| 软件信息融入结果 | 软件档案合并到清理结果内部，不单独设置“软件档案”页签 |
| 默认先隔离 | 对适合隔离的普通文件，默认移入应用隔离区，用户观察后再恢复或彻底清除 |
| 历史归入个人中心 | 清理记录和总结位于“个人中心 → 清理记录”，与个人主页形成完整的成果展示 |
| 空间数据真实可解释 | 文件占用、隔离占用和磁盘可用空间净变化分别展示，不把隔离量算作释放量 |
| 执行结果如实记录 | 成功、失败、跳过、待条件满足分别记录，部分成功不能显示成全部成功 |

界面不设置“查看示例结果”“查看清理记录”“查看本次记录”“全部记录”这类额外跳转按钮，也不设置“载入隔离示例”入口。清理记录中的“全部记录”可以保留为时间筛选选项。

隔离文件的“来源记录”链接、个人主页中的最近动态链接保留，用于追溯具体批次。

## 3. 功能范围

### 3.1 首版目标能力

- 深度扫描：识别软件与文件归属，区分文件作用，检查进程占用、组件引用与处理条件。
- 分类决策：按软件展开类别，逐项选择，提供推荐操作与影响说明。
- 清理方案：执行前汇总待处理内容、保留内容、执行方式、前置条件和确认事项。
- 隔离管理：统一查看隔离文件，批量恢复，确认后彻底清除，追溯来源。
- 本地个人主页：编辑昵称和简介，展示累计成果、分类分布和最近动态。
- 清理账本：记录每次选择、实际操作、文件大小、状态变化和空间复核。
- 阶段总结：按最近 7 天、最近 30 天、全部记录生成总结。

### 3.2 后续扩展候选

应用卸载、大文件、重复文件、相似照片、跨磁盘搬迁和系统状态监控可以后续评估，不因参考 Lemon 而自动进入首版范围。Windows 适配、云同步、公开个人主页也尚未确定。

本版不安排自动定期删除隔离内容，也不默认启用后台自动清理。

## 4. 桌面窗口与 Lemon 参考方向

参考 [腾讯柠檬清理官方网站](https://lemon.qq.com/) 中“按应用定制扫描、提供专业建议、简约操作”的产品方向。具体窗口分区、顶部菜单、隔离闭环与个人中心依据本次讨论设计；不将未逐屏核对的尺寸、颜色或布局表述为 Lemon 的已验证设计。

### 4.1 本轮修订依据

用户明确指出此前设计不够符合桌面端。主要问题是大标题、独立卡片和页面跳转过多，信息沿纵向堆叠，操作位置容易随内容移动。

| 反馈对应的问题 | v2 的设计回应 |
| --- | --- |
| 界面像信息展示页，清理任务不够集中 | 一个稳定主窗口，内容围绕当前任务排布 |
| 独立圆角卡片过多 | 使用连续工作区、细分隔线和列表；仅必要的确认内容使用独立容器 |
| 标题与说明占用大量首屏空间 | 页面名称、筛选和必要操作收进紧凑工具栏 |
| 长内容把操作按钮推到页面底部 | 顶部工具栏和底部操作区持续可见，列表及检查器内部滚动 |
| 查看解释需要反复展开并改变整体高度 | 结果列表与项目详情检查器并排，选择项目时更新右侧详情 |
| 个人中心像一张长网页 | 紧凑资料行、内部页签、指标条、分类列表与活动列表 |

### 4.2 主窗口规格

| 项目 | 本版建议 |
| --- | --- |
| 默认窗口 | 约 980 × 700 个逻辑单位，允许用户缩放；最终尺寸由原生布局验证 |
| 窗口控制 | 采用 macOS 原生标题栏与窗口控制区；原型仅呈现其视觉结构 |
| 主导航 | 顶部固定“概览、深度清理、隔离区、个人中心”，不设置主导航侧栏 |
| 本地工具栏 | 页面标题、筛选、重新体检等紧凑排列，不使用网页英雄区 |
| 内容工作区 | 在当前窗口内切换任务，列表、详情和进度保留明确边界 |
| 滚动方式 | 内容区局部滚动，避免整窗作为长页面滚动；上下工具区保持可见 |
| 底部操作区 | 有选择或执行任务时固定展示数量、大小与当前主操作 |
| 窄预览 | 列表与详情按需上下重排，保证内容可访问；正式桌面最小窗口尺寸另行验证 |

主窗口是排版的基准，不采用移动端卡片堆叠反向决定桌面布局。

### 4.3 全局窗口结构

```text
┌──────────────────────────────────────────────────────────────┐
│ 窗口控制  澄清       概览  深度清理  隔离区  个人中心     本机 │
├──────────────────────────────────────────────────────────────┤
│ 紧凑本地工具栏：当前任务 / 筛选                 必要操作      │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│                 有边界的内容工作区                           │
│          列表与详情可分别滚动，工具区不跟随滚走                │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│ 已选数量 / 大小 / 当前状态                    当前主操作      │
└──────────────────────────────────────────────────────────────┘
```

底部操作栏只在需要持续确认选择或执行状态时出现，不要求每页都有。设置等低频功能可放入原生应用菜单，不增加第五个主页面。

结果列表与详情检查器是页面内部工作区，不构成第二套主导航。

### 4.4 视觉与组件

- **连续表面**：以中性灰白或深灰的工作区为基础，用细线分隔工具栏、列表、检查器和操作区。
- **紧凑文字**：页面名称使用工具面板级标题；列表名称、类别、占用、建议和影响保持清晰的阅读顺序。
- **有限强调色**：v2 建议以绿色突出当前主操作与选中反馈；风险同时使用文字及橙色或红色表达。
- **克制圆角**：按钮、分段控件和确认 sheet 使用适当圆角；软件分组、指标、列表不逐个套独立卡片。
- **一致控件**：采用复选框、分段切换、下拉筛选、列表选中和附属确认 sheet，减少自造的展示组件。
- **明确状态**：可操作、已选择、正在检查、待条件满足、失败、已完成分别显示，不能只依赖颜色区分。

### 4.5 桌面交互规范

- 以一个主窗口完成体检、选择、确认、执行和查看结果，避免任务间反复开新页面。
- 结果的主列表选择和右侧详情联动；勾选用于加入方案，查看详情不自动勾选。
- 清理方案在当前工作区中审阅；彻底清除等高风险操作使用附属于当前窗口的确认 sheet。
- sheet 打开时明确确认范围，键盘焦点进入确认区；取消后回到触发操作。支持 Escape 取消，Enter 不绕过必要确认。
- 普通行的补充说明就地展示或放在检查器中，不为每条说明单独弹窗。
- 数值、单位和状态对齐；键盘焦点、选中状态、禁用原因清晰可见。
- 窗口缩小时优先缩减辅助留白，再调整列宽；必要时将详情改为行内展开，不隐藏关键影响和主操作。
- 高风险信息放在执行前，不能仅在操作完成后提示。

```text
├─ 深度清理
│  ├─ 分类结果（内含软件档案）
│  ├─ 本次处理方案
│  ├─ 执行进度
│  └─ 完成结果
├─ 隔离区
│  ├─ 隔离文件列表
│  ├─ 恢复
│  ├─ 彻底清除
│  └─ 来源记录
└─ 个人中心
   ├─ 我的主页
   │  ├─ 个人资料
   │  ├─ 累计成果
   │  ├─ 分类分布
   │  └─ 最近动态
   └─ 清理记录
      ├─ 时间筛选
      ├─ 批次与明细
      ├─ 操作时间线 / 空间复核
      └─ 本期总结
```

默认流程：

```text
选择检查范围 → 只读扫描 → 查看分类与建议 → 分项选择
→ 确认本次方案 → 复查执行条件 → 隔离可处理文件
→ 查看结果 → 在隔离区观察 → 恢复或确认彻底清除
→ 复核空间 → 在个人中心查看记录和总结
```

用户也可以主动选择直接删除。需要原生工具处理或前置条件未满足的项目进入待处理计划，完成条件后重新检查；不能绕过复查直接执行旧方案。

## 6. 页面设计

### 6.1 概览：清理开始前

**页面目标**：让用户了解当前磁盘状态、检查范围与默认保留策略，并开始体检。

采用中央磁盘与扫描任务、右侧检查范围的连续工作区。容量展示、扫描按钮和进度在稳定位置切换；右侧通过分隔线组织设置，不包装成多个独立卡片：

```text
┌──────────────────────────────────────────────────────────────┐
│ 存储概览（紧凑工具栏）                                       │
├──────────────────────────────────────┬───────────────────────┤
│             当前磁盘                 │ 本次检查范围          │
│        容量图与可用空间              │ □ 缓存与日志          │
│                                      │ □ 旧版本与残留        │
│          开始深度体检                │ □ 开发环境            │
│ 扫描时切换为进度与取消操作            │                       │
│                                      │ 默认保留与注意事项    │
└──────────────────────────────────────┴───────────────────────┘
```

页面内容：

| 区域 | 内容与行为 |
| --- | --- |
| 磁盘状态 | 磁盘名称、总容量、已用空间、可用空间、简洁容量图；真实产品显示读取时间 |
| 检查范围 | 缓存与日志、旧版本与卸载残留、开发环境等扫描范围；选择检查范围不等于授权删除 |
| 保留说明 | 聊天资料、书签、密码、个人设置等默认建议保留；可在结果中调整 |
| 主操作 | “开始深度体检”；点击后显示当前阶段与“取消体检” |
| 扫描阶段 | 识别软件 → 分类文件 → 核查占用与依赖 → 生成建议 |

概览围绕一次体检任务布局，不额外堆叠运营横幅、成果卡片或记录快捷按钮。扫描开始后主区域原位显示进度与取消操作，窗口尺寸保持稳定。

不能在扫描前显示虚构的“可释放空间”。权限不足、部分范围未扫描、扫描取消需要显示覆盖范围，用户可以查看已经完成的有效结果。

### 6.2 深度清理：分类结果

**页面目标**：让用户在理解用途和影响后，决定每个软件具体处理哪些类别。

采用左侧软件分组紧凑列表、右侧项目详情检查器。顶部筛选与底部操作固定，列表和检查器各自在内容区滚动：

```text
┌──────────────────────────────────────────────────────────────┐
│ 扫描结果                         扫描范围 / 重新体检          │
│ 已发现文件占用 · 已选占用 · 默认保留用户数据占用               │
│ 全部 / 缓存 / 日志 / 旧版本 / 用户数据 / 条件处理              │
├───────────────────────────────────┬──────────────────────────┤
│ 软件 A                            │ 项目详情检查器           │
│  ☑ 缓存      大小  建议清理        │ 软件归属与路径           │
│    影响：首次加载可能重新下载      │ 文件用途与判断依据       │
│  ☐ 用户资料  大小  建议保留        │ 建议 / 影响范围          │
│ 软件 B                            │ 前置条件 / 恢复限制      │
│  ☐ 运行组件  大小  条件处理        │                          │
│    列表内部滚动                   │ 详情内部滚动             │
├───────────────────────────────────┴──────────────────────────┤
│ 已选 X 项 · 文件占用 Y                     查看本次方案       │
└──────────────────────────────────────────────────────────────┘
```

软件分组可展开，类别独立选择。软件层级的批量选择需要呈现全选、部分选中、未选中状态；批量选中用户资料时，仍需在确认方案中汇总提醒。

推荐操作和简短影响在列表中直接可见，完整解释放入右侧检查器。点击项目名称或详情操作会更新检查器，不改变勾选状态；点击复选框只调整方案。当前查看项与已勾选项使用不同反馈，避免混淆。

主列表按“内容、占用、建议”对齐，软件组使用紧凑分组行与展开控制。底部始终显示已选项数、文件占用和“查看本次方案”，无需滚到列表末尾。不能要求用户打开多个窗口才能知道清理后果。

筛选只改变当前显示内容，不悄悄修改已选方案。提供“恢复推荐选择”“全选当前类别”“全部取消选择”，并明确批量操作的作用范围。

#### 软件档案如何融入结果

软件档案用于建立文件与软件、功能、依赖之间的关系，为建议提供依据。它服务于当下决策，不占用独立页签。

| 档案信息 | 用途 |
| --- | --- |
| 软件名称、标识、安装位置、当前版本 | 确认文件属于谁，区分同名软件或多个安装副本 |
| 数据目录与类别 | 区分缓存、设置、数据库、下载内容和组件 |
| 引用关系与进程占用 | 判断旧组件是否仍在使用、依赖是否被多个项目共享 |
| 识别证据、规则版本、检查时间 | 解释建议来自什么判断，便于后续复核 |
| 处理前提与恢复限制 | 告诉用户当前能否处理，以及处理后的影响 |

不能只根据文件名、修改时间或目录大小认定文件无用。无法确认归属的项目应显示“待确认”，不加入推荐选择。

### 6.3 本次方案：执行前确认

这是“深度清理”中的步骤，不增加顶部主菜单。审阅仍在原主窗口内完成：左侧为本次项目列表，右侧为处理方式、保留摘要和必要确认；项目列表可滚动，底部的执行按钮保持可见。

确认界面依次展示：

1. **本次可处理内容**：按软件和类别列出数量、大小、建议与影响。
2. **待条件满足内容**：列出已选择但暂不能执行的项目，以及具体前置条件。
3. **本次保留内容**：尤其明确用户资料、在用组件和未选类别。
4. **处理方式**：默认先隔离，用户可主动改为直接删除。
5. **必要确认**：涉及用户资料时确认影响范围；直接删除时确认无法从隔离区恢复。
6. **主操作**：根据当前方案显示“移入隔离区”“直接删除”或“保存待处理计划”。

执行前重新核对文件归属、文件变化、占用、权限与引用关系。条件发生变化时停止相关项目，给出原因并允许返回修改，不能用扫描时的旧结论直接执行。

确认应绑定当前所选项目和处理方式。修改选择或切换方式后，需要重新确认受影响的事项。

### 6.4 执行进度与完成结果

执行进度替换当前工作区中的任务内容，顶部主导航和窗口尺寸保持稳定。底部显示当前项目、已处理数量及必要的停止操作；完成后在同一区域呈现结果摘要与逐项状态，避免增加一张长篇完成页。

执行过程中显示当前项目、已处理数量、成功与失败数量，允许在安全边界停止后续操作。不能把中断前已经完成的操作视为自动撤销。

完成界面分别列出：

- 已隔离的项目和文件占用。
- 已删除的项目和文件占用。
- 待条件满足、跳过或失败的项目及原因。
- 磁盘净变化的复核状态。

有隔离文件时提供“前往隔离区”，同时提供“返回清理结果”。没有隔离内容时不突出无关操作。记录自动写入个人中心，不再增加“查看本次记录”按钮。

### 6.5 隔离区

**页面目标**：统一管理仍然存在、可以尝试恢复的隔离内容。

采用一个连续列表工作区：顶部紧凑显示当前数量和占用，中央是可滚动的项目列表，底部固定选择摘要及批量操作。文件不逐个放入独立卡片。

```text
┌──────────────────────────────────────────────────────────────┐
│ 隔离区                        当前项目数 / 当前隔离占用      │
│ 同盘隔离仍占空间；彻底清除需再次确认                          │
├──────────────────────────────────────────────────────────────┤
│ 选择  软件 / 类别 / 内容       大小  隔离时间  来源记录       │
│  □    软件 A · 缓存                                           │
│  □    软件 B · 用户资料                                       │
├──────────────────────────────────────────────────────────────┤
│ 已选 X 项 · Y                         恢复所选  彻底清除所选  │
└──────────────────────────────────────────────────────────────┘
```

规则：

- 只显示当前状态为“已隔离”的项目；待处理计划不属于隔离文件。
- 支持逐项选择、全选、批量恢复和批量彻底清除。
- 记录原始路径、隔离位置、大小、时间与来源批次，便于恢复和追溯。
- 恢复前检查原位置、文件冲突和必要权限；有同名内容时不静默覆盖。
- 点击“彻底清除所选”打开附属于主窗口的确认 sheet，显示所选项目、总大小和用户资料提醒；背景列表暂时不可操作，确认只作用于这次选择。
- sheet 中保留清楚的“取消”和“确认彻底清除”，需要的确认勾选完成前不允许执行；关闭后恢复列表焦点和当前选择。
- 改变选择或取消确认后，原确认失效。
- 不自动过期删除；恢复与清除结果追加回原清理记录。
- 空状态显示简洁说明与“去深度清理”。

隔离区主要管理当前文件，清理记录主要保留历史事实。记录里的隔离项跳转到隔离区处理，避免两处维护不同操作状态。

### 6.6 个人中心：我的主页

**页面目标**：以个人主页的形式展示整理成果，并承载清理记录入口。

页面顶部采用紧凑资料行：小尺寸头像或昵称首字、昵称、个人简介及“编辑资料”，标明本地个人主页、无需登录。资料行不使用大面积封面图或宣传式英雄区。

下方设置“我的主页 / 清理记录”两个内部页签，在同一窗口工作区内切换。累计成果使用一条指标带；分类分布与最近动态使用由分隔线组织的列表，长内容在各自内容区滚动。

“我的主页”展示：

| 区域 | 内容 |
| --- | --- |
| 累计成果 | 累计处理批次、已复核磁盘净变化、当前隔离占用 |
| 分类分布 | 按缓存、日志、旧版本等统计已删除文件占用，并注明统计口径 |
| 最近动态 | 最近的隔离、删除、恢复或复核活动，点击进入对应记录 |
| 空状态 | 尚无记录时显示说明，引导完成首次体检 |

主页累计统计不受“清理记录”中的最近 7 天、最近 30 天筛选影响。文件路径和资料名称不直接展示在主页汇总中。

个人主页首先是本机可展示的成果页；公开分享、账号体系和云同步不属于已确认能力。

### 6.7 个人中心：清理记录与总结

页面上方的紧凑工具栏提供时间筛选和“生成本期总结”，其下是一条本期指标带。中间为可滚动的批次列表，选中或展开批次查看明细与时间线；筛选和主要操作保持可见。总结使用附属于当前窗口的独立面板，提供关闭和选中复制操作；背景记录列表保留尺寸与滚动位置，不被总结区域挤压。支持 Escape 关闭并返回触发按钮。

每个批次至少展示：

- 创建时间、最近操作时间、处理方式、涉及软件。
- 本次选中、保留、待处理的类别与大小。
- 实际成功、失败、跳过和等待条件的数量。
- 单项建议、影响范围、前置条件与操作结果。
- 隔离、恢复、删除、空间复核等事件。
- 清理前后磁盘读数、复核时间及覆盖的删除操作。

批次可以经历多次后续操作。例如先隔离，数天后恢复一部分、删除另一部分；仍归属同一来源批次，追加新的事件。

从隔离区或最近动态进入来源记录时，如果目标不在当前时间筛选内，切换到能够显示目标的范围并展开该记录，避免跳转后看不到内容。

本期总结包括：时间范围、涉及批次、已删除文件占用、已复核磁盘净变化、当前隔离占用、恢复量、待复核次数、按软件与类别的分布，以及待处理和失败说明。

当前原型支持生成和复制演示总结；正式产品可在该位置增加 Markdown 导出。

## 7. 分类清理与建议规则

### 7.1 所有类别可选择，执行路径有区别

| 类别 | 默认建议 | 典型影响范围 | 执行要求 |
| --- | --- | --- | --- |
| 可重建缓存 | 确认归属后建议清理 | 首次打开变慢、资源重新下载、部分离线能力 | 检查占用；排除数据库和个人资料 |
| 过期日志 | 建议清理过期部分 | 历史故障排查信息 | 保留近期或仍需诊断的日志，依据明确规则 |
| 旧版本、重复更新副本 | 确认未引用后建议清理 | 更新、回退或旧版使用 | 检查当前版本、更新状态、引用关系 |
| 用户资料 | 建议保留 | 聊天资料、书签、密码、设置、备份、离线文件 | 可选；执行前汇总影响，核对同步与备份需求 |
| 当前运行组件 | 建议保留或替换后处理 | 应用启动、插件、连接器 | 可加入方案；替代方案与应用验证完成后复查 |
| 仍被加载的旧组件 | 退出后复查 | 正在运行的进程、页面、任务 | 未解除占用前保持待处理 |
| 共享依赖与包仓库 | 使用工具支持的清理流程 | 多个项目、安装与离线开发 | 检查引用，优先使用包管理器原生流程 |
| 项目依赖 | 活跃项目建议保留 | 构建、开发服务、离线运行 | 停止任务，确认可重装，明确排除源码和锁文件 |
| AI 模型等功能资源 | 根据功能需求决定 | 设备端 AI 等对应功能 | 优先通过所属软件设置处理，复查实际结果 |
| 归属不明确的内容 | 待确认 | 当前无法可靠说明 | 可加入待确认方案，不加入自动推荐执行范围 |

上述为规则框架。具体文件的建议必须来自本次扫描证据，不能把示例软件的分类结论直接套用于真实电脑。

### 7.2 每个项目的说明模板

每个项目使用一致的说明顺序：

1. **内容是什么**：文件作用与所属软件。
2. **建议怎么做**：建议清理、建议保留、退出后复查或通过原生设置处理。
3. **为什么**：归属、可重建性、版本、引用等依据。
4. **影响谁**：具体软件、功能、账号、项目或共享使用方；未知时明确标注。
5. **需要先做什么**：退出进程、检查备份、停止任务、验证替代组件等。
6. **能否恢复**：隔离可尝试恢复；直接删除或彻底清除后无法从隔离区恢复；重新下载不等于恢复个人资料。

### 7.3 区分建议、选择与状态

| 维度 | 示例 | 含义 |
| --- | --- | --- |
| 推荐操作 | 建议清理 / 建议保留 / 条件处理 / 待确认 | 软件给出的判断 |
| 用户选择 | 已选择 / 未选择 | 用户想纳入哪些内容 |
| 执行状态 | 待检查 / 可处理 / 待条件满足 / 处理中 / 已隔离 / 已恢复 / 已删除 / 失败 / 已跳过 | 实际发生到哪一步 |

建议保留的项目仍然可以选择；条件未满足的项目不会因已选择而直接删除。权限不足时解释原因和可选处理路径，不伪装执行成功。

## 8. 隔离、回收站与真正删除

### 8.1 首版默认流程

默认使用**应用自己管理的隔离区**，以便保存原始位置、归属与来源记录。

```text
原位置中的文件
  ├─ 默认：移入隔离区 → 观察 → 恢复到原位置
  │                              或
  │                         确认彻底清除 → 删除 → 复核空间
  └─ 用户主动选择直接删除 → 确认影响 → 删除 → 复核空间
```

默认流程下，第一次是隔离，第二次确认彻底清除才执行删除。用户主动选择直接删除时，第一次执行就会删除。

系统回收站可以作为未来独立的处理方式评估，本版不把隔离区和系统回收站混为一个入口，也不安排“隔离后再送回收站”的隐含步骤。

### 8.2 空间与恢复边界

- 同一磁盘内隔离仍占空间，不能在隔离完成时宣称已经释放对应容量。
- 隔离目录不足以容纳操作、权限不满足或文件状态变化时，应停止相关项目，不能静默退化成直接删除。
- 恢复需要核对原位置、冲突与文件完整性；隔离不能保证任何场景下都能无条件恢复。
- “彻底清除”表示从隔离区执行删除，之后无法通过本软件的隔离区恢复；它不代表安全擦除或取证意义上的不可恢复。

## 9. 记录与空间统计

### 9.1 三类空间指标必须分开

| 指标 | 计算依据 | 使用位置 |
| --- | --- | --- |
| 文件占用 | 实际扫描或操作对应的文件大小；明确逻辑大小与磁盘占用口径 | 结果、方案、单项记录 |
| 当前隔离占用 | 当前仍处于隔离状态的文件占用 | 隔离区、个人主页、总结 |
| 已复核磁盘净变化 | 同一磁盘或卷可用空间的前后读数之差 | 完成结果、历史、个人主页、总结 |

底层以字节记录，显示统一单位，不能混用 GB 与 GiB 而不标注。硬链接、共享数据等造成的大小差异需要在引擎中处理，无法准确计算时说明口径和限制。

磁盘净变化使用实际读数；其他程序同时写入、系统后台活动等也会影响读数，因此它不是对清理行为独占收益的绝对归因。净变化允许为零或负数，不能强行改成预计正值。

### 9.2 防止重复累计

- 扫描出的候选量、已选量、保留量、待处理量不算成功清理成果。
- 隔离只增加当前隔离占用，不增加已删除文件量。
- 隔离后彻底清除，才记录删除事件；同一项不能在隔离和删除时各算一次释放。
- 恢复减少当前隔离占用，并单独记录恢复量。
- 失败、跳过不计成功数量或成功容量。
- 每次空间复核关联尚未覆盖的删除事件，避免重复把同一次空间变化计入累计值。
- 如果一次复核覆盖多个批次，保存一次测量及关联关系，不能给每个批次复制同一个净变化值。

### 9.3 时间统计规则

按照各事件实际发生时间统计，不能只按最初批次创建时间归类。

例如：10 月 1 日隔离，10 月 10 日彻底清除，10 月 11 日复核空间。隔离、删除和复核分别计入对应日期；以 10 月 10 日为开始的统计范围应包含删除事件，即使原批次创建得更早。

“当前隔离占用”始终是当前所有批次的存量，需要标明它不受本期筛选限制。个人主页的累计指标也不受清理记录筛选影响。

### 9.4 原生版本建议的数据结构

| 对象 | 关键字段 |
| --- | --- |
| 扫描项 | 唯一标识、软件归属、类别、原始路径、文件标识、逻辑大小、占用大小、数量、检查时间 |
| 建议与证据 | 推荐操作、影响范围、前置条件、恢复限制、识别证据、规则版本 |
| 处理批次 | 批次标识、创建时间、用户选择、保留摘要、处理方式、确认范围、状态 |
| 文件操作结果 | 实际执行项目、前后位置、成功或失败、原因、实际数量与大小 |
| 操作事件 | 事件标识、来源批次、操作类型、发生时间、涉及项目、执行结果 |
| 空间复核 | 测量标识、磁盘或卷标识、前后时间与可用空间读数、关联删除事件、测量说明 |
| 隔离索引 | 当前隔离位置、原始路径、来源批次、完整性信息、当前状态 |
| 个人资料 | 本地昵称、简介与必要偏好 |

事件追加保存，后续操作不覆盖历史事实。重复点击、重试或恢复后再次清理需要通过操作标识区分，既避免重复计数，也保留真实发生的独立操作。

## 10. 原生落地要求

建议把界面、扫描、决策、执行和记录分开，避免界面勾选直接变成文件删除命令。

| 模块 | 主要职责 |
| --- | --- |
| 桌面界面 | 展示结果、承接选择与确认，提供进度和解释 |
| 扫描与归属识别 | 只读枚举，收集软件、目录、占用与引用证据 |
| 规则与决策 | 输出建议、影响、条件和执行路径，不凭大小或年龄单独下结论 |
| 执行协调 | 核对确认范围，执行前复查，按项目处理并上报真实结果 |
| 隔离与恢复 | 保存清单，可靠迁移，检查完整性，处理恢复冲突 |
| 本地账本与统计 | 持久化批次、事件、测量与状态，生成汇总 |

关键约束：

- 扫描不删除文件；确认后才进入执行阶段。
- 文件归属、路径边界和执行时的文件身份必须重新核对，避免目录变化或链接跳转造成越界处理。
- 不把“清缓存”扩展成卸载软件本体，不把“清依赖”扩展成删除源码。
- 进程占用、共享引用、原生设置流程未验证完成时保持待处理。
- 清理中断后可以从本地账本恢复状态，逐项核对已经完成与尚未完成的操作。
- 数据保存失败应明确提示并阻止依赖可恢复记录的后续危险操作，不能只在内存中假设记录已保存。
- 产品采用本地优先的数据方案；路径、会话名称、资料明细不默认对外上传。未来分享或导出需明确内容范围。

原生开发框架尚未选定，应在确认目标系统、权限机制和分发方式后决定；不能把当前界面原型视为已经可安装使用的清理程序。

2. **建立只读扫描能力**：优先支持少量可验证的软件规则，展示真实归属、大小、影响与覆盖范围。
3. **实现隔离闭环**：完成本地账本、执行前复查、隔离、恢复、冲突处理和中断恢复。
4. **接入删除与真实统计**：完成确认删除、逐项结果、磁盘复核、事件去重和期间汇总。
5. **扩展条件处理**：逐步接入原生设置、包管理器与共享依赖处理，验证后再扩大支持范围。

## 12. 验收要点

- [ ] 四个主菜单位于顶部；清理记录仅作为个人中心的内部内容组织。
- [ ] 桌面窗口缩放和列表滚动时，工具栏与需要固定的底部操作持续可见。
- [ ] 不使用网页英雄区、大标题和大量独立卡片组织主工作流。
- [ ] 列表选择、查看详情和加入清理方案三种行为清楚区分，检查器不会暗中改变勾选。
- [ ] 隔离区彻底清除使用确认 sheet，焦点进入、取消返回与必要确认行为可验证。
- [ ] 窄预览能够访问全部关键内容，不反向把正式桌面设计变为移动端卡片流。
- [ ] 概览能完成范围选择、开始体检、查看进度与取消。
- [ ] 同一软件可以只选缓存、保留用户资料，且界面明确显示这一差异。
- [ ] 所有扫描类别都可加入方案；建议保留与暂不能执行不被混成同一种状态。
- [ ] 列表直接显示推荐与简短影响；完整依据、条件和恢复限制可查看。
- [ ] 涉及用户资料和直接删除时，确认内容与本次选择一致；修改后旧确认失效。
- [ ] 条件未满足、失败和跳过的项目不计入成功成果。
- [ ] 同盘隔离不显示为已释放空间；隔离、删除、恢复状态能正确转换。
- [ ] 恢复遇到冲突不静默覆盖；彻底清除仅作用于已确认的隔离选择。
- [ ] 隔离、恢复、删除和复核能够追溯到来源批次，历史事件不被覆盖。
- [ ] 文件占用、当前隔离占用、磁盘净变化有独立标签和计算口径。
- [ ] 跨日期操作按事件时间计入期间，重复复核不重复累计。
- [ ] 从隔离区进入旧记录时，目标记录可见并展开。
- [ ] 个人主页累计指标不受历史筛选影响；总结明确期间与当前存量的区别。
- [ ] 原型演示数据有清晰标记，真实版本不生成伪造的扫描和清理成果。
