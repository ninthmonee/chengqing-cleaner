# 澄清：产品设计方案

更新日期：2026-11-03。基于当前 [index.html](../index.html) 重新整理；本次核对文件为 800 行，SHA-256 前缀 `2ea7fba39faf`。

本文以新版原型作为页面与交互基线。第 1 至 6 节描述当前设计，第 7 节列出尚未实现的改进提案；真实引擎、存储和模型接入见 [开发方案](technical-architecture.md)。

## 1. 产品定位与设计目标

澄清帮助用户理解文件属于谁、有什么用途、处理后影响什么，再按类别作决定。典型任务是清理一个应用的可重建缓存，同时保留资料、偏好和仍有引用的资源。

体验围绕一次完整任务展开：检查范围 → 扫描 → 理解与选择 → 审阅 → 处理 → 隔离管理与记录追溯。默认隔离用于观察和尝试恢复，确认删除后才有可能获得磁盘空间；两种阶段分别表达。

当前所有文件、归属证据、容量和处理结果均为演示。AI 已有配置与解释界面，但未接入真实服务；产品方案中的“扫描”“恢复”“删除”均指当前模拟交互。

## 2. 界面基线与信息架构

### 2.1 窗口与信息层级

| 区域 | 当前设计 |
| --- | --- |
| 启动窗口 | 默认 386 × 617 px，首页标题“磁盘扫描”，中央水位仪表、容量指标、仪表下方“开始扫描” |
| 扫描与后续工作区 | 扫描开始后宽度展开至 1000 px，高度保持 617 px；扫描结束及后续结果、隔离、记录页面仍保持展开 |
| 标题栏 | 检查范围及数量、隔离区、清理记录、设置四个入口；扫描时范围入口禁用 |
| 内容与操作 | 主内容区整体滚动；结果、审阅、完成页的操作追加在内容末尾，当前没有固定外部底栏 |
| 设置窗口 | 默认 560 × 640 px，含“供应商配置 / 外观主题”页签，可拖动边缘缩放 |
| AI 解释窗口 | 默认 640 × 560 px，可缩放；尺寸与设置窗口分别在本次会话内记忆 |
| 其他对话框 | 范围配置、恢复、清除及总结贴合主窗口内容区，不改变主窗口尺寸 |

这些是 CSS 逻辑像素。主窗口宽度受页面可用宽度约束，设置和 AI 窗口也受视口约束；主窗口高度目前固定，短屏幕可能需要页面滚动。

### 2.2 功能组织

```text
澄清
├─ 清理工作区：首页 → 扫描 → 结果与详情 → 确认方案 → 完成
├─ 检查范围：10 项范围、推荐范围、检查全部、保存或开始扫描
├─ 隔离区：当前存量、选择、恢复、彻底清除、来源记录
├─ 清理记录：期间筛选、统计、批次时间线、生成与复制总结
├─ 设置：供应商配置 / 外观主题
└─ 菜单栏面板：演示系统状态、缓存扫描、审阅与隔离
```

“询问 AI”位于结果单项的行内详情末尾。当前没有首页 AI 按钮、全局聊天入口、提问输入框或聊天历史；源码中的扫描前和总览建议模板尚无可见入口。清理记录已移除昵称、简介和编辑资料，不设置个人中心。

## 3. 核心用户旅程

| 旅程 | 当前操作顺序 | 结束状态 |
| --- | --- | --- |
| 常规清理 | 调整范围 → 开始扫描 → 查看分类与影响 → 勾选 → 审阅 → 模拟隔离或删除 | 展示本次处理与待处理内容，建立清理批次 |
| 条件处理 | 选中旧运行时或离线模型 → 审阅 → 保存待处理计划 | 保留原内容，不计成功；重新检查目前只给固定提示 |
| 单项 AI 解释 | 展开详情 → 询问 AI → 生成示例建议 | 展示用途、影响与条件，不改变选择或执行状态 |
| 首次配置 AI | 顶部设置 → 选择供应商 → 填写字段 → 可选格式测试 → 保存 → 回到项目询问 AI | 配置仅当前会话有效；未配置时 AI 窗口提示关闭后去设置 |
| 隔离管理 | 打开隔离区 → 选择内容 → 恢复，或额外确认后清除 | 追加到来源批次；恢复只模拟无冲突成功 |
| 菜单栏快捷清理 | 扫描缓存或复用扫描结果 → 审阅 → 勾选确认 → 模拟隔离 | 与主工作区共用隔离内容和记录，不提供直接删除 |

## 4. 页面设计

### 4.1 首页与扫描

首页聚焦当前磁盘状态和一次扫描操作。环形内部水位表达磁盘占用；数字突出可用容量，外圈在扫描时改为表达进度。悬浮或聚焦仪表可查看磁盘明细。

检查范围移至标题栏。默认检查应用缓存、浏览器资源、日志与诊断、旧版本与更新副本、卸载残留、开发构建与依赖 6 项；下载与安装包、本地用户资料、应用偏好与设置、模型与功能资源 4 项按需开启。至少保留一项才能保存；单独保存只影响下一次扫描。

扫描时窗口展开，仪表与阶段信息在宽工作区左右排列，窄容器改为上下排列。“取消扫描”位于仪表下方。当前进度由定时器模拟，取消结果按范围内示例数组比例截取；完成后统一进入结果页。

### 4.2 结果、行内详情与审阅

结果按应用或来源连续分组，行内显示类别、建议和占用。筛选为全部、缓存、旧版本、卸载残留、用户资料、待处理；提供应用或用途搜索、占用优先与应用名称选项。没有独立日志筛选、分组折叠或应用级复选框。

查看详情与勾选分开，同一时间只展开一项。详情按“建议依据 → 处理影响 → 文件位置与恢复限制 → AI 解释”组织。筛选不清空隐藏选择；“选择当前结果”只操作可见集合，“恢复推荐”和“取消全选”作用于当前扫描全部可用结果。

审阅页列出已选、未选保留、可处理与待条件满足的项目。进入审阅默认选择隔离；更改处理方式使原确认失效。直接删除或所选包含当前 `data` 类型时，需额外勾选确认。

完成页分别展示本次隔离或删除占用、待处理数量和未复核净变化。当前处理同步模拟成功，没有执行进度、停止后续处理或失败分支。

### 4.3 隔离区与清理记录

隔离区先展示全部当前存量和项数，再提供全选、选择摘要、恢复和彻底清除，随后是项目列表。没有内容时使用简短空态。来源记录链接切至全部期间并展开对应批次。

清理记录直接组织时间筛选、期间统计、说明与批次列表。期间为最近 7 天、最近 30 天、全部记录；本期删除按事件时间统计，当前隔离存量不受期间影响。批次展开呈现当时所选、保留和后续事件。

“本期总结”使用代码计算和固定模板，可复制文本；没有报告文件导出，也不调用模型。

### 4.4 供应商配置与 AI 解释

设置默认打开“供应商配置”。当前提供 OpenAI、DeepSeek、Anthropic、通义千问、Ollama、自定义接口六种预设，包含 API Key、默认模型、接口地址和默认建议模型选择。预设地址和模型仅为演示值，不表示账号权限、服务可达或模型可用已验证。

字段支持密钥显隐、必填检查、模型 ID 和地址格式检查、错误定位、格式测试、保存及移除。Ollama 和自定义接口的密钥可选；其余四种必填。首次保存自动设为默认并启用示例建议；保存不要求先测试，移除默认配置会回退到其他已保存配置，移除最后一项后不可生成建议。

“测试连接”只模拟本地配置格式检查，不发送网络请求。AI 窗口展示供应商与模型、可展开的类别摘要，以及“生成示例建议”；延迟后显示本地模板的建议依据、影响和处理条件。摘要不包含完整路径、文件正文或密钥；当前没有真实上传。

AI 不改变勾选、不授权处理、不执行文件操作。未配置状态提示用户先关闭解释窗口，再通过顶部设置完成配置。

### 4.5 视觉与键盘

保留森林主题的深色底面和绿色主操作，以及其余 7 套主题；风险、建议、待处理同时使用文字表达。通过细分隔线和连续列表组织内容，行内解释服务于当前操作。

范围、设置、AI 解释和文件操作使用一致的按钮、表单与焦点样式。保留 ⌘ / Ctrl + 1、2、3 切换清理、隔离、记录；模态框打开时禁用这些快捷键。Escape 关闭弹窗，设置页签可用方向键切换；样式响应降低动态效果偏好。

## 5. 产品规则与演示边界

| 规则 | 当前口径 |
| --- | --- |
| 推荐、选择与条件 | “建议保留”仍可主动选择；固定 `ready=false` 项只保存待处理 |
| 内容分类 | 当前 `data` 混合资料、偏好、安装包与模型；“用户资料”统计、筛选及确认按该字段判断 |
| 隔离与删除 | 默认隔离，可选直接删除；恢复仅演示无冲突分支，清除需再次确认 |
| 空间统计 | 文件占用、隔离存量、删除占用和磁盘净变化分开；同盘隔离不计释放，磁盘读数不随模拟操作改变 |
| 批次与事件 | 提交方案建立批次；纯待处理不产生文件操作事件，恢复和清除追加来源批次 |
| 数据保存 | 仅主题尝试通过浏览器持久化；范围、文件状态、待处理、账本、供应商配置和密钥刷新重置 |
| AI 与总结 | AI 是单项解释模板演示；本期总结是另一套确定性模板，两者均未使用模型 |

当前没有真实扫描、文件身份与权限复查、持久化账本、失败恢复、空间测量或模型服务；框架与发布要求在开发方案中作为后续建议维护。

## 6. 本次重新检查的基准

新版仍为 6 个来源分组、11 类固定数据。初始会话的默认完整扫描发现 7 类 / 24.48 GB，推荐 5 类 / 14.24 GB；全范围为 11 类 / 39.02 GB，其中当前“用户资料”指标为 15.38 GB，包含安装包和模型。

快捷新扫描只检查应用缓存与浏览器资源，初始得到 2 类 / 4.50 GB；复用完整扫描时可包括开发构建缓存，共 3 类 / 11.30 GB。这是现状中的范围差异。

这组数值用于识别和核对当前演示版本，不是实际磁盘检测结果，也不作为生产版本的固定验收数值。

## 7. 下一轮设计改进提案（未实现）

以下提案保持新版页面结构，需在实施时同步原型与文档。本轮仅重新检查和编写方案，没有修改 HTML。

| 优先级 | 当前问题 | 拟议设计与验证结果 |
| --- | --- | --- |
| P0 | `data` 混合不同内容，安装包和模型也触发用户资料备份确认 | 分开定义内容类别、资料敏感性和处理条件；统计与确认对应真实影响 |
| P0 | 快捷扫描覆盖主窗口结果与选择；扫描完成会切走正在看的页面 | 区分任务结果和用户草稿；新任务不覆盖已审阅内容，完成时提供可进入结果的通知 |
| P0 | 待处理数量与当前可见列表可能不一致，复查和取消未闭环 | 让待处理集合稳定可访问，计数与列表一致；按资源说明条件，支持取消意向和重新审阅 |
| P1 | 长结果或说明会把操作推至滚动末尾 | 验证主操作可达性，再决定增加选择摘要或局部粘性操作区；不将固定底栏写成既有设计 |
| P1 | 新快捷扫描与复用结果的缓存范围不同，审阅缺逐项影响 | 使用一致的缓存规则，展示实际范围、检查时间和影响摘要 |
| P1 | AI 未配置需关闭弹窗后绕回设置 | 提供明确的配置入口及配置后返回原项目的路径，保留上下文 |
| P1 | 设置初次聚焦可触发空密钥错误，重开已保存配置也可能提示需重存 | 区分未编辑、已编辑未保存、已保存及检查状态；验证用户未操作时的文案 |
| P1 | “应用名称”选项没有实际重排应用分组 | 让分组顺序符合选项名称，切换排序保留选择与展开项 |

真实能力建议先完成少量规则的只读扫描，再验证隔离、恢复、持久化记录和异常结果，之后开放永久删除、空间复核与真实 AI。各阶段的技术退出条件集中在开发方案中维护，不另拆路线图。
