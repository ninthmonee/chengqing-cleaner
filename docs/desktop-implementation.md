# 澄清桌面端实现方案

日期：2026 年 11 月 2 日

状态：开发建议稿

设计基准：[当前交互原型](../index.html)

配套文档：[技术架构设计](technical-architecture.md)

建议首版面向 macOS，采用 React 实现现有界面，使用 Tauri 承载桌面窗口，使用 Rust 实现扫描、规则判断、文件操作和本地账本。先交付可验证的扫描与隔离恢复闭环，再开放直接删除，最后增加 AI 辅助分析。

## 1 设计基准与交付范围

当前仓库包含 HTML 交互原型和方案文档，没有真实清理引擎。原型里的容量、CPU、内存、文件清单、扫描进度与操作结果均为演示；除主题偏好外，主要业务状态保存在当前页面会话内。

### 1.1 按当前原型实现的界面

| 区域 | 当前设计 | 桌面实现要求 |
| --- | --- | --- |
| 主窗口 | 标题栏、内容区、固定底部操作栏 | 一个可缩放的主窗口，内容局部滚动，系统提供窗口控制 |
| 导航 | 标题栏右侧隔离区、清理记录、应用设置三个图标 | 保留当前入口，不增加侧栏或四个文字页签 |
| 首页 | 环形水位容量仪表、检查范围摘要、开始扫描 | 水位表示磁盘已用比例；外圈在扫描时表示任务进度 |
| 检查范围 | 10 个可选范围，默认选择 6 个 | 配置独立持久化；开始扫描时冻结本次范围 |
| 清理结果 | 按应用分组、类别行、建议、占用、行内详情 | 查看详情与勾选分离；维持单项展开，保留滚动位置 |
| 审阅方案 | 已选内容、明确保留、可处理与待处理、处理方式 | 展示真实复查结果、影响与恢复限制 |
| 隔离区 | 勾选、恢复、彻底清除、来源记录 | 加入路径冲突、缺失文件、外部变更和失败状态 |
| 清理记录 | 本地资料、期间统计、批次与时间线、总结 | 保留本地个人资料，不增加登录和独立个人中心导航 |
| 外观 | 森林夜色、冰川白昼、深海蓝、银雾灰、曜石黑、月光紫、玫瑰石、极地青 | 复用 8 套主题，全窗口同步，支持降低动态效果 |
| 菜单栏面板 | 磁盘、CPU、内存、扫描进度、缓存审阅 | 真实系统状态入口，与主窗口共享任务和账本 |

早期 [产品设计](product-design.md) 中的“四菜单、右侧检查器、独立个人中心”为历史方案；本次界面实现以本表和 `index.html` 为准。早期文件中的用户资料保留、执行复查、隔离恢复和统计约束继续适用。

### 1.2 首版能力边界

首版建议支持 macOS 13 及以上，优先在 Apple Silicon 验证；该版本是产品支持建议，最终须由窗口、权限、签名安装的兼容性试验确定。Intel 发布取决于对应真机验收，不能只因能够编译便宣称支持。

首批覆盖启动盘内经过验证的用户目录，选择 3 至 5 个软件或工具链建立规则；建议先验证 Xcode 构建缓存、应用缓存和历史诊断日志。微信、Safari 的路径和数据边界必须按实际软件及系统版本核实，原型中的示例路径不能直接成为生产删除规则。

10 个检查范围全部保留。尚未有可靠规则的范围显示“尚未支持”或“仅识别候选”，不能显示成已完成检查。旧运行时、共享依赖、离线模型等可加入待处理计划，先由所属软件管理；“可选择”不等于“可立即执行”。

首版不加入自动清理、定期清空隔离区、系统目录强制处理、root 常驻服务、云同步和账户系统。Windows 作为后续平台适配，不与首个 macOS 版本同时承诺。

## 2 从网页原型迁移到桌面窗口

### 2.1 窗口与原生系统元素

原型中的 `.system-bar`、桌面背景 `.desktop-stage` 和三色圆点是展示环境。安装后的应用只渲染窗口内容，菜单栏、窗口阴影、圆角和红黄绿按钮交由 macOS。标题栏采用原生窗口控制与定制内容区域组合，拖动区域避开按钮。

主窗口内容尺寸参考原型约 1080 × 760 个逻辑单位；建议最小 900 × 640，最终以 13 英寸屏幕可用区域验证。原型在 560 高度仍可展示属于演示适配，不直接用作生产最小尺寸。主窗口记录上次尺寸和位置；显示器变化后回到可见区域。

默认关闭主窗口时隐藏窗口并保留菜单栏入口；首次关闭给予简短说明。只有用户选择“退出澄清”才结束进程。有写操作时，退出先停止接收新任务，再在当前文件操作完成并记账后退出；不得强制中断后宣称任务完成。

菜单栏使用真实状态图标。快捷面板优先采用托盘定位的小窗口；若焦点、全屏空间或多显示器行为不符合验收，再通过最小 AppKit 适配层实现原生面板。系统时钟、Wi-Fi 和其他系统图标不属于应用界面。

### 2.2 组件与界面状态拆分

| 组件或页面 | 职责 |
| --- | --- |
| `AppShell`、`TitlebarActions`、`ActionBar` | 窗口框架、页面入口、固定操作区 |
| `OverviewPage`、`StorageOrb`、`ScanProgress` | 容量与扫描状态，提供相同数值的文字说明 |
| `ScanScopeDialog` | 10 项范围、推荐范围、全部范围、未支持提示 |
| `ResultsPage`、`ApplicationGroup`、`CategoryRow` | 应用分组、筛选、勾选、排序与汇总 |
| `EvidenceDisclosure` | 行内显示理由、证据、影响、路径与恢复限制 |
| `PlanReviewPage`、`ExecutionPage` | 审阅、复查、逐项执行进度和结果 |
| `VaultPage`、`RestoreConflictDialog` | 隔离存量、恢复、冲突处理与清除 |
| `HistoryPage`、`BatchTimeline`、`SummaryDialog` | 资料、期间统计、来源定位与总结 |
| `AppearanceDialog`、`TrayPanel` | 全局主题与菜单栏快捷流程 |

原型的全局 `S` 拆为三个层次：页面临时状态保存在前端，业务状态保存在 Rust 服务和 SQLite，系统状态来自 macOS 适配层。窗口之间只同步服务端事实；主窗口与快捷面板不分别维护一套待删除清单。

前端提供 `MockDesktopClient` 与 `TauriDesktopClient` 两个适配器。开发和视觉验收可使用演示数据；正式构建默认只接真实服务，演示模式有明确标识。保留原 `index.html` 作为对照，不直接扩展其中的全量 `innerHTML` 重绘逻辑。

### 2.3 视觉和交互标准

提取颜色、文字、间距、圆角、控件高度与动效为设计变量，将 `--green` 等颜色名改为 `--accent` 等语义名。保留默认森林主题的绿色主操作，其他主题使用各自强调色；保留连续分组列表、细分隔线和当前水位仪表，不引入另一套组件库的默认卡片风格。优先使用无样式的可访问组件或已有简单原生 HTML 控件。

主题由 Rust 设置服务持久化，启动创建窗口前加载，主窗口与快捷面板接收相同的设置版本，避免开窗闪色。深浅主题同时更新 WebView 色彩方案和窗口外观；图表颜色也从变量读取，移除 SVG 中仅适合深色的固定色值。

支持 Tab、Shift+Tab、Escape 和原有 ⌘1 清理、⌘2 隔离区、⌘3 清理记录；增加 ⌘, 设置、⌘F 搜索和标准窗口快捷键。文件操作不能由 Enter 绕过确认。折叠、搜索、勾选不丢失焦点；展开详情不改变勾选。

## 3 主要流程的实现设计

### 3.1 磁盘与系统读数

读取当前数据卷的总量和可用量，明确指标口径与采样时间。水位按同一组读数计算；扫描外圈和容量水位使用独立状态。

原型“应用与资料 / 系统与其他”的两个数值无法靠一次容量 API 准确得到。首版优先展示总量、已用、可用；分类数据只有在覆盖范围与算法可解释时才显示，并标记“已识别范围”或“估算”。不得用全部已用空间减去本次扫描量，直接命名为“系统占用”。

CPU 使用率按两次采样差计算；内存显示已采用的统计口径，不提供“释放内存”操作。建议面板可见时 2 秒采样，隐藏后暂停 CPU 和内存曲线；磁盘读数在打开面板和操作后刷新，空闲时低频更新。具体耗电预算由实机测量确定。

### 3.2 扫描

流程为“冻结范围 → 发现软件 → 按规则枚举 → 采集证据 → 分类与建议 → 完成或部分完成”。扫描不修改目标文件；保存本地扫描记录属于应用内部状态写入。

枚举期间总文件数未知，显示阶段、已检查数量和当前软件，不使用计时器制造百分比。总工作量明确后才能给出该阶段进度。取消后只提交证据完整的项目，其他范围注明未完成、权限不足或未支持。

扫描结果以“应用下的类别”为用户选择单位，但类别映射到固定文件清单或可验证的完整目录单元。用户确认后新生成的缓存不能自动纳入该确认。目录在执行前改变时重新计算影响并要求重审。

### 3.3 结果选择与审阅

筛选、搜索和排序只改变视图，不改变已选集合。“选择当前结果”仅操作当前筛选；被隐藏的已选项持续提示并在审阅页完整列出。恢复推荐只勾选证据完整且符合已验证规则的建议清理项。

每项分开显示三个维度：文件类别、推荐操作、执行条件。用户资料可选择但默认建议保留；共享依赖、模型、运行时可能显示待条件满足。不能用一个 `ready` 布尔值同时代表权限、引用、安全性与确认状态。

审阅页展示完整选择、明确保留、可执行、待处理、处理方式及恢复限制。保存待处理计划不等于授权未来自动执行；条件解除后必须复查和重新确认。

### 3.4 执行与结果

最终确认绑定方案版本和处理方式。确认后由 Rust 重新核对路径边界、文件身份、目录内容变化、权限、应用状态和适用的引用条件。变化项停止执行并解释原因，不能自动扩大处理范围。

执行期间底栏显示当前项、完成数、失败数和“停止后续处理”。停止只作用于尚未开始的项目；部分成功如实展示，已完成操作留在账本。隔离失败不降级为直接删除。

结果页面扩展为已隔离、已删除、待处理、跳过、失败、待核对几类结果。隔离占用与删除占用分开；空间复核尚未完成时显示“测量中 / 未复核”，不显示虚构的绿色释放量。

### 3.5 隔离与恢复

首版仅对同一卷且满足规则的普通文件进行隔离，默认按已确认清单逐成员移动到应用私有隔离目录；整体目录移动仅用于可验证静止且内容受控的目录。跨卷项目保存为待处理。隔离目录不参与后续扫描，也不作为可执行资源目录。

恢复前检查原卷、原位置权限和同名项。冲突时提供“保留现有文件并恢复为新名称”“选择新位置”“跳过”；默认不覆盖。新名称或新位置作为新的恢复方案重新确认，记录最终路径。

彻底清除是独立操作，展示所选内容与不可通过隔离区恢复的事实。该功能不宣称安全擦除，也不承诺绕过系统快照立即获得对应空间。

### 3.6 菜单栏快捷清理

快捷入口只处理经过验证的可重建缓存。流程保留“只读扫描 → 审阅缓存与影响 → 确认隔离”，不直接永久删除。缓存白名单、复查、执行器和账本与主窗口完全共用。

快捷扫描优先拥有独立结果集合；复用完整扫描时必须明确来源和时间，不覆盖主窗口已审阅的扫描快照。扫描与写操作由同一调度器仲裁，不能同时从两个窗口执行重叠目标。

### 3.7 清理记录与总结

清理批次记录当时的已选、保留、证据和确认范围；恢复、清除继续追加到来源批次。期间统计按事件发生时间筛选，批次因本期发生恢复或清除事件也可以出现在本期记录中。

删除文件占用、当前隔离存量、恢复占用和磁盘可用空间净变化独立展示。当前隔离存量不随 7 天、30 天筛选变化；期间长度使用本地时间展示，事件保存绝对时间。

总结先由代码计算，再套用固定模板。首版无需模型即可生成和复制总结；AI 后续只组织文字。系统状态、空间数字和操作成功情况都来自真实服务。

## 4 迁移前必须修正的原型行为

| 原型实现 | 生产替换 |
| --- | --- |
| `setInterval` 模拟扫描百分比，按数组比例生成取消结果 | 实际扫描任务、覆盖范围与完整证据检查 |
| `files`、`ready`、`removed` 作为全部业务状态 | 不可变扫描快照、分项前置条件、持久化生命周期 |
| 执行函数同步将所有 ready 项标记成功 | 逐项复查、异步执行、错误分类和中断核对 |
| 恢复直接设 `removed=false` | 检查真实路径和冲突，再记录恢复结果 |
| 示例路径、固定容量、CPU 和内存 | 经验证的本地证据与系统 API |
| 本地账本和资料刷新后丢失 | SQLite 账本及设置服务 |
| 偏好、模型、下载包均复用 `data` 类型 | 扫描范围、文件类别、建议、执行条件分别建模 |
| 总结把文件占用直接相加 | 明确逻辑大小与分配占用，重叠去重，实测空间单列 |

## 5 分阶段交付与验收

按 1 名前端、1 名熟悉 Rust 和 macOS 的工程师、测试参与的条件，建议安排约 8 至 10 周，属于有限规则覆盖的内部测试版估算。系统权限差异、软件规则验证和故障恢复会影响工期；大范围商业发布另行评估。

| 阶段 | 参考时间 | 交付与退出条件 |
| --- | --- | --- |
| M0 原生可行性 | 第 1 周 | 窗口、菜单栏、主题、权限探测、签名安装、同卷移动恢复实机验证；确定支持系统与分发渠道 |
| M1 桌面界面 | 第 2 周 | 拆分组件，贯通演示适配器，保留当前页面结构和有效交互，修正第 4 节模拟行为；最低窗口尺寸、8 主题、键盘与焦点验收 |
| M2 只读引擎 | 第 3 至 4 周 | 接通 3 至 5 个规则样本，证据与部分扫描持久化；未支持与无权限不伪装完成 |
| M3 隔离恢复 | 第 5 至 6 周 | 执行前复查、同卷隔离、冲突恢复、逐项账本和崩溃核对；通过故障注入后再开放真实写入 |
| M4 删除和记录 | 第 7 至 8 周 | 直接删除与隔离清除、磁盘复核、期间总结；统计不重复，部分失败可追溯 |
| M5 发布加固 | 第 9 至 10 周 | 菜单栏真实读数、耗电调优、签名公证、更新和安装升级回归；形成内部测试包 |

工作依赖为 M0 → M1/M2 → M3 → M4 → M5；界面和引擎可在接口确定后并行。AI 辅助分析独立排期，不阻塞本地版本交付。

关键验收包括：只读扫描不改变目标；选中不等于执行许可；执行范围变化使确认失效；恢复不静默覆盖；任何失败不记成功；重启可核对未完成操作；同盘隔离不计释放；一项删除和一组空间测量不重复累计。测试方法与模块边界见 [技术架构设计](technical-architecture.md)。

## 6 建议先落实的决策

| 决策 | 默认建议 | 调整条件 |
| --- | --- | --- |
| 平台与分发 | macOS 优先，Developer ID 签名并公证后以 DMG 分发 | 若必须首发 Mac App Store，先重验沙盒和扫描范围 |
| 桌面框架 | Tauri 2、React、Rust | 若团队以 Swift 为主且长期只做 macOS，可改为 SwiftUI/AppKit，沿用服务契约 |
| 文件范围 | 启动盘用户可写、规则明确的目录 | 通过跨卷恢复和权限验收后再扩展 |
| 隔离策略 | 默认隔离，手动清除，无自动到期删除 | 自动化能力作为独立产品决策 |
| AI | 本地规则先行，模型可选 | 有评测收益且用户启用云端分析后接入 |

上述建议足以开始 M0 与界面拆分，不需要先确定模型供应商、账户体系或云端后端。
